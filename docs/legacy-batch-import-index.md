# Legacy JSONL 取込みの索引スナップショット

`annotate import-batch` によるディレクトリ取込みでは、最初に stem 形式の `custom_id` を照合した時点でファイル名・alias の索引を取得する。取得した索引は、同じ操作内の残りの JSONL ファイルでも共有する。phash 形式のみを扱う操作では、この索引を取得しない。

## スナップショットの寿命と整合性

- **操作内限定の一時データ**: 索引は 1 回の取込み操作内でのみ有効であり、サービスやプロジェクトをまたいで保持しない。
- **単一ファイル取込み時の挙動**: 単一の JSONL ファイルを取り込む場合は、毎回最新の索引を取得する。
- **並行変更の扱い**: ディレクトリ取込みの実行中に別処理が追加・変更したファイル名や alias は、実行中の索引には反映されない。次回の取込み時に反映される。なお、phash 照合や注釈保存を含む処理全体のトランザクション保証を追加するものではない。
- **既存挙動の維持**: 重複 stem の代表選択、実ファイル名を優先する alias フォールバック、未一致およびパースエラーの集計、dry-run 時の保存抑止は従来どおり維持する。

## 検証

- `tests/unit/services/test_batch_import_service.py`: 画像数 `N`(1、500、501、1000、10000)、ファイル数 `F`(1、3)、通常保存および dry-run の組み合わせを検証している。各ファイルが 1 レコードの場合、全索引の構築回数は `F` 回から 1 回へ、合成画像の走査行数は `FN` から `N` へ減少する。alias が `A` 件ある一般形での取得量は、1 操作あたり `N+A` 件である。なお、SQL 実行時間や速度倍率は測定していない。
- `tests/unit/services/test_batch_image_matcher.py`: 実 SQLite リポジトリを用い、alias の解決と重複 stem の選択動作も確認している。
