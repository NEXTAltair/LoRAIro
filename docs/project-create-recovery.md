# project create の失敗復旧

プロジェクト作成がディレクトリ作成、メタデータ書き込み、DB ファイル作成の途中で失敗した場合、その呼び出しで新規作成したプロジェクト領域を削除します。新規作成した親ディレクトリは空の場合だけ削除します。既存プロジェクト・ファイル・未完成プロジェクトを自動削除することはありません。任意の別プロセスによるパス差し替え・同時作成の安全性保証は対象外です（2026-09-06 の利用方針決定）。新規作成したPathだけを追跡し、通常の一回の呼び出し内の失敗を復旧します。

メタデータは新規領域内の `.lorairo-project.pending` に書き込み、書き込みとclose、ディレクトリ・DBファイル作成が完了してから `.lorairo-project` として公開します。途中失敗でcleanupできなくても正式マーカーは残らず、一覧・名前検索から除外されます。

障害を解消した後、同じ名前の `lorairo-cli project create NAME` を再実行できます。正常作成済みの名前を再指定した場合の `ALREADY_EXISTS` は従来どおりです。

cleanup 自体が失敗した場合、`--json` の stdout 最終行（`kind=error`, `code=INTERNAL_ERROR`, 終了コード 1）の `details` に以下を出力します。

- `original_error`: 作成処理の元エラー。API 例外の `__cause__` にも保持します。
- `cleanup_errors`: cleanup に失敗したパスとエラーの一覧。
- `residual_paths`: cleanup を完了できなかったプロジェクト領域・親ディレクトリ。
- `recovery`: ファイルシステム障害の解消と同名create再実行、残留内容を別途確認する案内。

残留する親ディレクトリには別のファイルが入っていることがあります。残留パスをまとめて再帰削除せず、内容を確認してください。今回の作成で残ったpending領域は同名再試行を妨げず、既存パスと衝突すれば連番の新規領域を使います。残留領域の自動再利用・削除はしません。旧版が正式マーカーを残した未完成プロジェクトは自動修復しません。クラッシュ後の自動清掃や電源断への永続性保証も対象外です。
