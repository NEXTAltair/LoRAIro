# `project create` の失敗復旧

## 失敗時の自動復旧

プロジェクト作成処理がディレクトリ作成、メタデータ書き込み、DB ファイル作成の途中で失敗した場合、その呼び出しで新規作成したプロジェクト領域を自動で削除する。新規作成した親ディレクトリは、中身が空の場合のみ削除する。既存のプロジェクト、ファイル、未完成プロジェクトを自動削除することはない。

この復旧処理は、通常の 1 回の呼び出し内で新規作成したパスだけを追跡して行う。任意の別プロセスによるパス差し替えや同時作成に対する安全性保証は対象外である(2026-09-06 の利用方針決定)。

## マーカーの公開手順

メタデータはまず新規領域内の `.lorairo-project.pending` へ書き込む。書き込みとクローズ、さらにディレクトリと DB ファイルの作成がすべて完了した段階で `.lorairo-project` として公開する。途中失敗によりクリーンアップできなかった場合でも正式マーカーは残らないため、プロジェクト一覧や名前検索からは除外される。

## 障害解消後の再実行

障害を解消した後、同じ名前を指定して `lorairo-cli project create NAME` を再実行できる。なお、正常に作成済みの名前を再指定した場合に `ALREADY_EXISTS` となる挙動は従来どおりである。

## クリーンアップ失敗時のエラー出力

クリーンアップ自体が失敗した場合、`--json` 指定時の stdout 最終行(`kind=error`、`code=INTERNAL_ERROR`、終了コード 1)の `details` に以下の項目を出力する。

- `original_error`: 作成処理で発生した元のエラー。API 例外の `__cause__` にも保持する
- `cleanup_errors`: クリーンアップに失敗したパスとエラーの一覧
- `residual_paths`: クリーンアップを完了できなかったプロジェクト領域および親ディレクトリ
- `recovery`: ファイルシステム障害の解消、同名の `create` 再実行、残留内容の個別確認を促す案内

## 残留パスの扱いと対象外の挙動

残留した親ディレクトリには、別のファイルが含まれている場合がある。残留パスをまとめて再帰削除せず、必ず内容を確認してから対処する。

- 今回の作成失敗で残った `pending` 領域は、同名の再試行を妨げない。既存パスと衝突する場合は連番の新規領域を使用する
- 残留領域の自動再利用や自動削除は行わない
- 旧版が正式マーカーを残した未完成プロジェクトの自動修復は行わない
- クラッシュ後の自動清掃や電源断に対する永続性保証は対象外である
