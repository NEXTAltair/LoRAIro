# 画像一括登録のキャンセルと再登録

GUI のフォルダ一括登録は、ジョブタブの「実行中 / 履歴（同期ジョブ）」の行にある「キャンセル」で止める
(進捗の確認とキャンセルはジョブタブで行う、ADR 0066 §4)。キャンセルは GUI を待たせない協調キャンセルで、
登録スレッドを強制終了しない。

## 止まる位置

キャンセルを押すと、行は「停止待ち」、ステータスバーは「キャンセル中」になる。登録は次のいずれかで止まる。

| 位置 | 止まり方 |
|---|---|
| 関連ファイル (.txt / .caption) の先読み中 | 次のファイルを読む前に止まる。DB には何も書かない |
| 画像と画像の間 | 次の画像に進まない |
| タグ DB の検索・登録中 | 実行中の SQL を SQLite の progress handler で打ち切る。別の検索、競合時の retry、個別検索へのフォールバック、tag_id 無しでの縮退保存には進まず、画像エラーとしても記録しない |

止まると、行は「キャンセル」と「中断: N/M 件処理済み」を、登録サマリは「■ 登録中断」と処理済み件数を示す。

## 画像ごとの状態

| 画像 | DB とストレージに残るもの |
|---|---|
| 完了済み | 元画像のコピー、画像行、512px、関連タグとキャプション。サマリの件数と内訳に入る |
| 中断対象 (タグ DB の処理中に止めた 1 枚) | 元画像のコピー・画像行・512px は確定済みのことがある。関連タグはロールバックされて残らない。サマリに「中断対象」として名前が出る |
| 未着手 | 何も書かれない |

サブフォルダ共通タグは全画像の登録後にまとめて付けるため、中断した登録では付かない。

## 回復方法

同じフォルダをもう一度登録する。完了済みと中断対象の画像は重複として扱われ、関連 .txt のタグを既存の画像へ
取り込む (同じタグ行は増えない)。未着手の画像は新規に登録される。サブフォルダ共通タグもこのとき付く
(既に同じタグを持つ画像は飛ばす)。

## 強制終了した場合

アプリを強制終了したときも、DB は SQLite のジャーナルで commit 前の行がロールバックされ、整合性は保たれる。
ただし元画像のコピー中または画像行の書き込み中に終了すると、DB 行を持たない元画像のコピーがストレージに残る。
再登録は既存のファイル名を避けて別名で保存するため、この孤児ファイルは自動では消えない。
`images.stored_image_path` から参照されないことを確認してから手動で削除する。
途中終了をなるべく避け、キャンセルで止める。
