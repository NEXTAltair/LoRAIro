# 画像一括登録のキャンセルと再登録

GUI のフォルダ一括登録は、ジョブタブの「実行中 / 履歴(同期ジョブ)」の行にある「キャンセル」ボタンで停止する(進捗確認とキャンセルはジョブタブで行う。ADR 0066 §4)。キャンセルは GUI を待たせない協調キャンセルであり、登録スレッドを強制終了しない。

## 停止する位置

「キャンセル」を押すと、対象の行は「停止待ち」、ステータスバーは「キャンセル中」へ切り替わる。登録処理は次のいずれかの位置で停止する。

| 位置 | 停止のしかた |
|---|---|
| 関連ファイル(`.txt` / `.caption`)の先読み中 | 次のファイルを読む前に停止する。DB には何も書き込まない |
| 画像と画像の間 | 次の画像へ進まず停止する |
| タグ DB の検索・登録中 | 実行中の SQL を SQLite の progress handler で打ち切る。別の検索、競合時のリトライ、個別検索へのフォールバック、`tag_id` なしでの縮退保存には進まず、画像エラーとしても記録しない |

停止が完了すると、行には「キャンセル」と「中断: N/M 件処理済み」が表示され、登録サマリには「■ 登録中断」と処理済み件数が表示される。

## 画像ごとの状態

| 画像 | DB とストレージに残るもの |
|---|---|
| 完了済み | 元画像のコピー、画像行、512px 画像、関連タグとキャプションが残る。サマリの件数と内訳に含まれる |
| 中断対象(タグ DB の処理中に止めた 1 枚) | 元画像のコピー、画像行、512px 画像は確定済みの場合がある。関連タグはロールバックされて残らない。サマリに「中断対象」として名前が表示される |
| 未着手 | 何も書き込まれない |

サブフォルダ共通タグは全画像の登録完了後にまとめて付与するため、中断した登録では付与されない。

## 回復方法

同じフォルダをもう一度登録する。各画像の状態に応じて次のように処理される。

- **完了済み・中断対象の画像**: 重複画像として扱われ、関連 `.txt` のタグを既存画像へ取り込む(重複するタグ行は増えない)
- **未着手の画像**: 新規画像として登録される
- **サブフォルダ共通タグ**: 再登録の完了時に付与される(すでに同じタグを持つ画像はスキップされる)

## 強制終了した場合

アプリを強制終了した場合でも、SQLite のジャーナルにより commit 前の行はロールバックされるため、DB の整合性は保たれる。

ただし、元画像のコピー中または画像行の書き込み中に終了すると、DB 行を持たない元画像のコピーがストレージに残ることがある。再登録時は既存のファイル名を避けて別名で保存するため、この孤児ファイルは自動では消えない。`images.stored_image_path` から参照されていないことを確認したうえで手動削除する。途中終了は極力避け、キャンセル操作で停止する。
