# Agent harness restoration

LoRAIro owns its hook registrations, `.claude/hooks/rules/*.json` overrides,
`hook_teammate_monitor.py`, and UI generation. The common runtime and bootstrap
are generated by `NEXTAltair/altairs-agent-dev-kit`; do not copy its framework
back into `.claude/hooks` or `.codex/hooks`.

## Fresh checkout or linked worktree

Run from the target checkout with Python 3.12 or newer and Git on PATH:

```console
python -X utf8 scripts/install_agent_harness.py
```

On Linux, `python3` may be used for this command. The tracked Claude registrations
use `python`, so that executable must also be available to the agent process.
`make setup` includes this restoration step. No application dependency sync is
needed to restore or launch common hooks.

`agent-harness.lock.json` selects the upstream commit. The tracked
`.agent-kit/hooks.lock.json` identifies and hashes that branch's runtime.
Restoration verifies and publishes the immutable files under the shared main
checkout's `.agent-kit/runtimes/<digest>/`. A fresh linked worktree uses its own
tracked lock and overrides with that shared cache. No worktree-local `.venv` is
created. Consumer checks use the existing shared environment.

Claude and Codex registrations contain a compressed bootstrap generated by the
kit. The bootstrap resolves the active Git checkout from the process working
directory, verifies its lock and runtime before importing common code, and loads
consumer hooks from that active checkout. A stale `CLAUDE_PROJECT_DIR` or payload
`cwd` does not change the selected checkout. Run agents inside the intended
checkout; missing or corrupt runtime fails closed with a restoration diagnostic.
In LoRAIro, use the restoration command above rather than the kit repository's
`scripts/install_harness.py` path shown in the generic diagnostic.

## Updating the kit

Change the full commit in `agent-harness.lock.json`, then explicitly regenerate
registrations and the runtime lock:

```console
python -X utf8 scripts/install_agent_harness.py --refresh-wiring
```

Review and commit the source pin, `.agent-kit/hooks.lock.json`,
`.claude/settings.json`, and `.codex/hooks.json` together. This explicit migration
replaces the kit's event groups and rewires the known consumer event handlers;
review custom additions within those groups before accepting the diff. Other
Claude settings, local settings, project policy overrides, and Codex local
configuration remain owned by the consumer. Ordinary restoration never rewrites
registrations and refuses to repin an existing different runtime lock.
`--kit-source <trusted-checkout>` is an explicit development/offline override;
ordinary restoration still checks that source against the branch runtime lock.

A corrupt immutable cache entry is never overwritten automatically. Stop hook
sessions, move only the diagnosed `<digest>` directory aside, and rerun restore.
Do not remove a `.agent-kit/.pin-update` guard while its installer is running.

## Verification

```console
python -X utf8 -m unittest discover -s scripts/tests -v
python -X utf8 scripts/validate_harness.py
```

The launch tests download the pinned archive into a temporary fresh checkout,
create a linked worktree, exercise actual registrations from nested directories,
and verify active-branch overrides and teammate hooks without copied common
framework files. They require Git and network access to GitHub codeload.
