# エージェントハーネスの復元

LoRAIro はフック登録、`.claude/hooks/rules/*.json` の上書き設定、`hook_teammate_monitor.py`、および UI 生成を自ら管理する。共通ランタイムとブートストラップは `NEXTAltair/altairs-agent-dev-kit` によって生成される。そのフレームワークを `.claude/hooks` や `.codex/hooks` へ書き戻してはならない。

## 新規チェックアウトまたはリンクされた worktree

Claude / Codex を起動する前に、Python 3.12 以上と Git が PATH に通った通常のターミナル (PowerShell、cmd、または Linux シェル) から、対象のチェックアウトで以下を実行する。

```console
python -X utf8 scripts/install_agent_harness.py
```

このターミナルコマンドがコールドスタート時の復旧経路である。ランタイムが欠落していると、エージェントの PreToolUse フックがツール呼び出しを拒否するため、そのエージェント経由での復元依頼も通らない。初回の復元をエージェント自身に依頼してはならない。ブランチ切り替えによって未キャッシュのランタイムが選択された場合は、エージェントを停止し、通常のターミナルでコマンドを実行してからエージェントを再開する。`make setup` も同様であり、エージェントセッションを開く前に通常のターミナルで初回セットアップを実行する。

Linux ではこのコマンドに `python3` を使用してもよい。追跡済みの Claude 登録は `python` を参照するため、エージェントプロセスからも `python` 実行ファイルが利用可能でなければならない。`make setup` にはこの復元手順が含まれる。共通フックの復元や起動にあたって、アプリ依存関係の同期は不要である。

コンシューマー側は、フックの上書きによって通常の Python / ツールコマンドを `uv run` へリダイレクトする仕組みを廃止した。復元は標準ライブラリの Python を直接使い、アプリのチェックは選択された共有インタープリタまたは明示的な `uv run --no-sync` を使用する。

`agent-harness.lock.json` が上流コミットを指定し、追跡済みの `.agent-kit/hooks.lock.json` がそのブランチのランタイムを識別・ハッシュ化する。復元処理は不変ファイルを検証し、共有メインチェックアウトの `.agent-kit/runtimes/<digest>/` 配下へ公開する。新規のリンクされた worktree は、自身の追跡済みロックと上書き設定をその共有キャッシュと組み合わせて使用する。worktree ローカルの `.venv` は作成されない。コンシューマー側のチェックは既存の共有環境を使用する。

Claude と Codex の登録には、kit が生成した圧縮ブートストラップが含まれる。ブートストラップはプロセスの作業ディレクトリからアクティブな Git チェックアウトを解決し、共通コードをインポートする前にロックとランタイムを検証して、そのアクティブなチェックアウトからコンシューマーフックを読み込む。古い `CLAUDE_PROJECT_DIR` やペイロードの `cwd` によって選択チェックアウトが変わることはない。エージェントは意図したチェックアウト内で起動すること。ランタイムが欠落または破損している場合はフェイルクローズし、復元診断メッセージを出力する。LoRAIro では、汎用診断に表示される kit リポジトリ側の `scripts/install_harness.py` ではなく、上記の復元コマンドを使用する。

## kit の更新

`agent-harness.lock.json` のフルコミットを変更し、登録とランタイムロックを明示的に再生成する。

```console
python -X utf8 scripts/install_agent_harness.py --refresh-wiring
```

ソースのピン、`.agent-kit/hooks.lock.json`、`.claude/settings.json`、および `.codex/hooks.json` をレビューしてまとめてコミットする。この明示的な移行処理は kit のイベントグループを置き換え、既知のコンシューマーイベントハンドラーを再配線する。差分を受け入れる前に、それらのグループ内にあるカスタム追加を確認する。その他の Claude 設定、ローカル設定、プロジェクトポリシー上書き、および Codex ローカル設定は引き続きコンシューマー側が所有する。通常の復元処理が登録を書き換えることはなく、既存の異なるランタイムロックの再ピン留めも拒否する。`--kit-source <trusted-checkout>` は開発 / オフライン向けの明示的な上書きオプションであり、通常の復元ではこのソースもブランチのランタイムロックに対して検証される。

破損した不変キャッシュエントリが自動上書きされることはない。フックセッションを停止し、診断された `<digest>` ディレクトリだけを退避してから復元を再実行する。インストーラーの実行中に `.agent-kit/.pin-update` ガードを削除してはならない。

## 検証

```console
python -X utf8 -m pytest -o addopts="" scripts/tests -v
python -X utf8 scripts/validate_harness.py
```

起動テストは、ランタイムキャッシュがない状態で拒否されることを確認したあと、通常のターミナルコマンドで復旧してフック実行を検証する。さらに、ピン留めされたアーカイブを一時的な新規チェックアウトへダウンロードし、リンクされた worktree を作成して、ネストしたディレクトリから実際の登録を動作させる。共通フレームワークのコピーなしに、アクティブブランチの上書きとチームメートフックが機能することも確認する。これらのテストには Git および GitHub codeload へのネットワークアクセスが必要である。

## 外部スキルの再現性と出所

従来ピン留めされていなかった全 13 件の GitHub スキルは、すべて厳密なコミット指定へ移行済みである。既存の kit リリースタグは変更していない。復元処理は各リポジトリリビジョンをその実行中のみキャッシュするため、同一のピン留めソースから取得する複数スキルは 1 回のダウンロードを共有する。

- `wshobson/agents` の 6 スキルは `a30778f8c4e6b0a87567941b7cca4f534bf642b6` (2026-09-01) を使用する。独立したステージド CLI インストールは、6 件すべての**既存**ハッシュと一致し、ハッシュやスキル内容の更新は一切受け入れていない。現在のハッシュは 5 月の初期インポートではなく、2026-07-05 の LoRAIro `ddd40b80` / `2f444930` で導入されたものである。
- `vercel-labs/agent-skills` の 7 スキルは履歴コミット `b9c8ee0643d87d3c5a953d1e22382ff2ead39229` (2026-05-05) を使用する。以前追跡していた全ファイルを、LoRAIro `4e1d2cda` (2026-05-12) で最初にコミットされた対応ファイルとバイト単位で比較した。元の 7 件のロックハッシュは、保存された履歴内容と一致しない。元のハッシュが生成された正確な原因は**未証明**である。この修正はアルゴリズム原因の推測ではなく、リポジトリで追跡されたバイト列と独立したステージド `npx skills add` のダイジェストに基づいている。

`vercel-react-view-transitions` 以外の 6 つの Vercel スキルは、検査時点の最新コミット `063bee94c3f4df8453406c830b0a7df0f2860278` でも同じディレクトリハッシュを生成する。`vercel-react-view-transitions` は 8 月の変更を取り込まず、意図的に当初追跡していた内容へ復元している。

`deploy-to-vercel` には明示的な成果物例外が 1 点ある。選択した履歴ソースには上流の `Archive.zip` が存在していたが、LoRAIro の初回インポートでは追跡されていなかった。ピン留めされた完全なスキルにはその元のソース成果物が含まれる。履歴版と検査時点の現行アーカイブはいずれも同一の 11,314 バイトの ZIP (SHA-256: `37c0d035b3d2c6256105316a2492c1487f3688efa21f030a8a623a9f7f0ee02f`) である。当初追跡していた 3 ファイルは引き続きバイト単位で一致する。上記のディレクトリハッシュにはこの ZIP も含まれるが、復元中にアーカイブ内容が実行されることはない。

skills CLI の `github:owner/repo#<full SHA>` クローンフォールバックは SHA をブランチと解釈して失敗する。そのため `scripts/install_agent_skills.py` はフル SHA 参照を GitHub codeload 経由でダウンロードし、一時ディレクトリへ安全に展開したうえで、分離された一時プロジェクト内で CLI を呼び出して `computedHash` を検証する。一致した内容のみをコンシューマー側へコピーし、ハッシュ不一致時は既存のスキルファイルに触れない。復元後、CLI の一時ローカルパスや付随的な書き換えは受け入れず、GitHub の出所やその他エントリを含むプロジェクトロックをバイト単位で保持する。ブランチおよびタグ参照は、同じハッシュ拒否チェックを備えた既存の CLI 復元経路を引き続き使用する。

シンボリックリンク権限がない Windows 環境では、Claude スキルリンクに `.agents/skills` 配下の厳密に検証されたターゲットを指すディレクトリジャンクションを使用する。スキルディレクトリのコピーは行わない。誤ったターゲットを指す既存リンクは検証で拒否され、ターゲットディレクトリを走査・削除することなく修復される。Unix および権限を持つ Windows 環境では、引き続きディレクトリシンボリックリンクを使用する。
