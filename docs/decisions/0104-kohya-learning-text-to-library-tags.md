# ADR 0104: Kohya データセットの学習テキストをライブラリの Tag へ写す(擬似モデル KOHYA_DATASET)

## Context

Kohya 取り込みで保存した学習テキスト(手動で整理された精度の高いタグ)は、`dataset_learning_texts`(フォルダと画像の組)にのみ保持され、画像直下の `Tag` には書き込まれなかった(ADR 0098 の当初の方針)。そのため、通常の検索・タグ編集・通常の書き出しでは利用できない。

ライブラリ側へ写す操作は ADR 0098 で後続課題とされており、#1397 でも「現在のアノテーションへの反映は、履歴保存とは別の明示的な操作とする」と整理されている。

現在の `Tag` テーブルには由来を表す専用列が無く、区別に使える列は `model_id`・`existing`・`is_edited_manually` のみである。ただし `uq_tags_image_model_tag`(`image_id`, `model_id`, `tag`)の UNIQUE 制約により、`model_id` が異なれば同じ表記のタグ行を並存させられる。

## Decision

### 1. 取り込み時に常に写し、最新版の内容へ同期する

Kohya 取り込み(`DatasetImportService.import_directory`。CLI・GUI・親フォルダからの複数版の取り込みのすべてが通る)は、選択肢なしで常に、最後にそのデータセットの `KOHYA_DATASET` 行を同期する(`DatasetRepository.sync_kohya_tags_for_dataset`)。

- **最新版の規則**: データセットの確定済みの版(`is_working=False`)のうち、同じデータセットの他の確定済みの版の `parent_version_id` に指されていない版(親の版の連鎖の末端)で、ID が最大のものを最新版とする。版名・番号・日付からは判定しない。取り込みの順番(`dataset import <親フォルダ> --order ...` が `parent_version_id` の連鎖として記録する)が利用者の指定であり、順番の指定が無ければ最後に取り込んだ版が最新になる。作業中の版は最新版にも、最新版を隠す子にも数えない。
- **同期の対象**: そのデータセットのいずれかの版に属する画像。
- **正(desired)**: 画像ごとに、全データセットの最新版でその画像が属するフォルダの `.txt` の要素の和集合。同じ版の複数フォルダに属する画像はフォルダ間の和集合、複数のデータセットが同じ画像を使う場合はデータセットごとの最新版の和集合とする。
- **差分同期**: 画像の `KOHYA_DATASET` 行のうち正に無いものを削除し、足りないものを追加する。正に残る行は soft-reject 済みでもそのまま保つ。1 トランザクションで行う。

明示的な操作(`lorairo-cli dataset copy-tags`、`--dry-run` 対応)も、取り込み済みの版を写し直す手段として残す。

### 2. 専用の擬似モデル `KOHYA_DATASET` で由来を区別する

写したタグ行は、専用の擬似モデル `KOHYA_DATASET` の `model_id` に紐づけて保存する。

- モデル属性: `provider="user"`、`litellm_model_id="__kohya_dataset__"`、`model_types` なし、`requires_api_key=False`
- スキーマ変更は行わず、`MANUAL_EDIT` と同じく初回利用時にモデル行を作成する。
- 手入力・共通タグ(`MANUAL_EDIT`)や AI のタグ行とは別行として共存させ、`model_id` 単位で一括取り消しできるようにする。

### 3. 対象テキストの集約規則と表記の扱い

- 同じ画像が選択対象の複数フォルダに含まれる場合は、それらの学習テキスト要素の和集合を写す(選択していないフォルダは対象外とする)。
- 写す対象は 1 種類の拡張子のみとし、既定は `.txt`(タグ)とする。`.caption`(文章のキャプション)はカンマ区切り要素がタグにならないため、明示指定された場合のみ写す。
- 表記は学習テキストの要素をそのまま写す(ADR 0098 および #1448 の共通タグと同じく、`clean_format` もタグ DB での解決も行わず、`tag_id` は空とする)。
- 各行の属性は `existing=True`、`is_edited_manually=False` とする(取り込み元に既にあったタグであり、LoRAIro 上で手編集したものではないため)。

### 4. 追従の範囲と冪等性

- 取り込みのたびに、§1 の差分同期で最新版の内容へ追従させる。新しい版を取り込んで最新版が変わると、そのデータセット由来の古い要素の行は消える。
- 作業中の版の確定(`commit_working_version`)では再同期しない。必要なら `copy-tags` で写す。
- 明示的な写し直し(`copy-tags`)は追加のみを行い、既に `KOHYA_DATASET` の同じ行(ソフトリジェクト済みを含む)が存在する画像には触れない。
- 同期・写し直しのいずれも、他モデル(手入力の `MANUAL_EDIT`、AI、その他の擬似モデル)の `Tag` 行には触れない。

### 5. 既存のモデル除外処理との整合

`MANUAL_EDIT` と同様の除外処理は、モデル行の属性(`model_types` なし、`requires_api_key=False`)によって自動的に機能する。推論対象(`ModelSelectionService` のアノテーション対象判定)や WebAPI モデルの利用可否調整(`reconcile_api_model_availability`)からは自然に外れるため、除外処理へモデル名をハードコードして追加する箇所は無い。

なお、コード上で名前により `MANUAL_EDIT` を参照している残りの箇所は、すべてレーティング(`Rating`)または手動タグの書き込み先であり、`Tag` のみを書き込む本操作には該当しない。

### 6. 表示

- 出所区分(`ImageRepository._tag_source`)は `KOHYA_DATASET` の行を `"Dataset"` とする(`existing=True` で写すため、`Manual` 判定より前に分ける)。ADR 0111 の擬似モデルの表示区分に並ぶ。
- タグ欄は、同一表記に畳む前の行に `KOHYA_DATASET` を含むチップへ学習データセット由来の印を付け、由来(すべて / データセット / AI / 手入力)で絞り込めるようにする。
- 画像詳細の「学習に使ったデータセット」の表に、画像が属する全版のデータセット・版・フォルダ・繰り返し数を出す。行を選ぶと、その版・フォルダの `.txt` の要素に一致するタグをタグ欄で強調し、要素の一覧を表の下に読み取り専用で出す(新しい版で通常タグから消えた古い版のタグもここで確認する)。元の `.txt` の並び順は表示せず、要素は名前順に並べる。

改訂の経緯: 初版は「明示的な操作でだけ写し、自動追従しない」としていた。取り込んだ画像のタグ欄に何も出ず、学習テキストと通常タグの二重管理を利用者に意識させるだけだったため、取り込み時に常に写して最新版の内容へ同期する方式へ改めた。古い版をすべて足した和集合にすると直す前のタグが戻るため、最新版の内容だけを正とする。

## Consequences

- 取り込んだ画像は、取り込み直後から最新版のタグを通常の検索・タグ編集・通常の書き出しに表示する。検索の「モデル」ファセットにも `__kohya_dataset__` が他のモデルと同様に並ぶため、由来で絞り込める。
- 版・フォルダ・元の学習テキストといった詳細な由来までは追跡できない。これらが必要になった場合は、`Tag` テーブルに由来列を追加する(#1454 の案 C)。
- 元の表記をそのまま写すため、ライブラリ内の表記(アンダースコアと空白など)と揃わない場合がある。
- 取り込み済みの版への遡及反映は行わない(既存の `copy-tags` で写す)。版の編集・確定の GUI 化は後続課題とする。
- 1 つの版の取り込みで、その版の画像に加えて同じデータセットの過去の版の画像も同期対象になる。過去の版にしか無い画像の `KOHYA_DATASET` 行は消える。
