# ADR 0097: Clef をローカルモデル専用に変更

## Context

ユーザーは Clef をローカルモデルで使用し、Cloudflare ホスト API 対応を削除する方針を明示した。ADR 0094 のホスト API 優先方針と、それに基づく画面・設定・手順がこの意図と合致していなかった。

過去の試作では、llama.cpp b11435 と Clef-flash 9B Q4_K_M、および対応する画像プロジェクターを用い、GPU 10 層で実画像の判定動作を確認済みである。この実行ファイルと量子化モデルを再利用する。

## Decision

### ローカル専用化と外部通信の排除

- Clef の実行先をローカルのみに限定する。Cloudflare の認証設定、環境変数解決、ホスト通信クライアントは削除する。なお、他のアノテーションモデルの API 設定には影響しない。
- image-annotator-lib の `LocalDecisionClient` が、指定された `llama-server`、モデル、および `mmproj` を明示実行時に読み込む。同一設定では実行プロセスを共有して推論を直列化し、終了時に停止する。
- 起動先はループバックに固定し、外部 URL やホスト API へのフォールバックは設けない。プロキシ、リダイレクト、および起動時のモデルダウンロードは無効化する。

### 実行環境と設定仕様

- 対応 Python の下限を 3.12.4 とする。Windows 環境でも一時認証ファイルを配置するディレクトリのアクセス権を制限できるバージョンに合わせ、Python 3.12.0〜3.12.3 での導入を防ぐ。
- GUI の基本設定に「Clef(ローカル)」を設け、3 つのファイルパスと GPU 層数・コンテキスト長を指定できるようにする。既定値は GPU 10 層、コンテキスト長 4096、待機上限 300 秒とする。画像選択や検索操作だけではモデルを起動しない。

### 推論分割・鮮度管理・エラー処理

- LoRAIro は既存の型付き判定、警告、候補提案、手動修正、結果保存の仕組みを維持し、推論を最大 16 質問ずつに分割する。コンテキスト超過時は入力を黙って切り捨てず、失敗として扱う。
- スナップショットにはローカル実行ファイル・モデル・`mmproj` のパスとファイル状態(stat 情報)、GPU 層数、およびコンテキスト長を含める。ファイルや設定が変わった保存結果は古い判定とし、ホスト API 由来の旧結果も現在の判定には再利用しない。
- バッチ実行では、設定不備・ローカル接続失敗・タイムアウトが発生した時点で後続処理を停止し、完了済み結果と未評価を明確に区別する。

## Consequences

- API キーや Cloudflare アカウントが不要となり、画像と注釈はローカル PC 内で完結して評価される。
- モデルと対応ランタイムは事前に用意する必要がある。また、初回ロード時の待機と PC のメモリ・GPU リソース消費が発生する。
- 保存テーブルのスキーマ変更は不要である。旧認証設定は読み込み時に除去し、次回保存時に設定ファイルから削除する。旧判定は確認履歴として保持する。
- 本 ADR により、ADR 0094 の実行先・認証・通信設定に関する決定を置き換える。ADR 0095 および ADR 0096 の対象固定、結果保存、検索・手動修正の責務は維持する。
