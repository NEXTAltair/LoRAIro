# ADR 0097: Clef をローカルモデル専用に変更

## Context

ユーザーは Clef をローカルモデルで使用し、Cloudflare ホストAPI対応を削除する方針を明示した。
ADR 0094 のホストAPI優先方針と、その後の画面・設定・手順がこの意図に合っていなかった。
過去の試作では llama.cpp b11435 と Clef-flash 9B Q4_K_M、対応する画像プロジェクターを使い、
GPU 10層で実画像の判定を確認済み。実行ファイルと量子化モデルを再利用する。

## Decision

- Clef の実行先はローカルのみ。Cloudflare認証設定・環境変数解決・ホスト通信クライアントを削除する。
  他のアノテーションモデルのAPI設定には影響しない。
- image-annotator-lib の `LocalDecisionClient` が、指定された llama-server とモデル・mmproj を
  明示実行時に読み込む。同一設定では実行プロセスを共有し、推論を直列化する。終了時に停止する。
- 起動先はループバック固定。外部URLやホストAPIへのフォールバックは設けない。
  プロキシ・リダイレクト・起動時のモデルダウンロードを無効にする。
- GUIの基本設定に「Clef（ローカル）」を設け、3つのファイルとGPU層数・コンテキスト長を指定できる。
  既定はGPU 10層・コンテキスト4096・待機上限300秒。画像選択・検索でモデルは起動しない。
- LoRAIro は既存の型付き判定・警告・候補提案・手動修正・保存を維持し、推論を最大16質問ずつに分割する。
  コンテキスト超過は入力を黙って切り捨てず失敗として扱う。
- snapshot にローカル実行ファイル・モデル・mmproj のパスとstat情報、GPU層数・コンテキスト長を含める。
  ファイルや設定が変わった保存結果は古い判定になる。ホストAPI由来の旧結果も現在の判定に再利用しない。
- バッチは設定不備・ローカル接続失敗・タイムアウトで後続処理を止める。完了済み結果と未評価を区別する。

## Consequences

APIキーやCloudflareアカウントが不要になり、画像・注釈はこのPC内で評価される。
モデルと対応ランタイムは事前に用意する。初回ロードの待機とPCのメモリ・GPU利用が必要になる。
保存テーブルの変更は不要。旧認証設定は参照せず、旧判定は確認履歴として保持する。

ADR 0094 の実行先・認証・通信設定の決定を本ADRで置き換える。
ADR 0095 / 0096 の対象固定、結果保存、検索・手動修正の責務は維持する。
