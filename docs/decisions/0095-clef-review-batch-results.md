# ADR 0095: Clef アノテーション確認の固定対象バッチと画像別結果保持

> 2026-10-08 追記: Clef の実行先と認証設定は [ADR 0097](0097-clef-local-only.md) によりローカル専用へ変更した。

> 2026-11-23 追記: CLI は `--save-results` を明示した場合のみ結果を保存し、既定では保存しない。保存には GUI と同じ Store および規則(フィンガープリントと確認開始時刻による原子的 upsert)を使用する。また、ルートの `--read-only` オプションとは併用できない([LoRAIro #1603](https://github.com/NEXTAltair/LoRAIro/issues/1603))。

## Context

ADR 0094 の初期実装は選択画像の一時的な警告のみに対応していた。そのため画像を切り替えると結果が消えてしまい、複数画像の結果を見比べながら手動修正する作業には向かなかった。

ユーザーは、開始時に対象を固定したバックグラウンド処理、画像ごとの結果保持、および結果画面の警告から手動確認へ進む導線を求めている。なお、画面上の呼称は「アノテーション確認」とする。

## Decision

### 既存コンポーネントの再利用

既存のステージング集合、`WorkerManager`、Clef サービス、結果タブ、および検索画面の手動編集を再利用する。新しい通信ライブラリや別の生成モデル経路は追加しない。

### 対象固定とバッチ実行

- 明示操作によって開始時の対象画像 ID を順序付きの不変集合として取り込む。上限は最大 500 枚とする。
- バックグラウンドで全対象のスナップショットを読み取ってから API 呼び出しを開始する。実行中に選択やステージングが変更されても、実行対象は変更しない。

### 画像別結果の永続化と鮮度判定

- 画像ごとの最新結果を専用 Repository と追加テーブルへ保存する。保存項目は注釈 ID・原文・確率・状態・フィンガープリント・モデル・警告基準・確認時刻とし、再起動後も読み出せるようにする。
- 保存と通知は画像単位で行い、途中で中止しても完了済みの結果を保持する。
- 単画像処理とバッチ処理が並行実行された場合は、確認開始時刻を比較する原子的 upsert により、遅れて完了した古い処理が新しい結果を上書きすることを防ぐ。
- 原画像・注釈のフィンガープリントや判定モデル・基準が一致しない保存結果は、古い結果として表示する。履歴の内容自体は保持するが、古い一致確率を現在の注釈に対する判定として表示しない。

### 結果タブと手動編集導線

- 結果タブに画像ごとの警告・失敗・未評価を表示し、対象画像を検索画面の既存手動編集で開けるようにする。
- 一覧は DB から直近 500 枚を取得し、古い結果かどうかの判定もワーカーで行う。初回取得は結果タブの表示時に実行し、メイン画面の構築中にはワーカーを起動しない。
- 直近 500 枚より前の保存結果は、画像の詳細欄から個別に参照できる。
- 警告を理由に注釈や `reviewed` 状態を自動変更しない。

### CLI の保存方針

GUI での結果保存は明示した確認処理に属する。CLI の既存読み取り専用実行では保存を行わない。

## Rationale

既存の選択状態やステージング状態はユーザー操作で随時変化するため、実行対象の不変コピーを分離する必要がある。API 送信前にスナップショットを読み取ることで、待機中に発生した変更もフィンガープリントによる無効化の対象にできる。

画像単位で保存すれば、中止や失敗によって他画像の完了結果が失われる事態を防げる。また、専用テーブルを設けることでタグの信頼度(confidence)や品質スコアと確認結果を混同せず、既存の手動編集をそのまま活用できる。

## Consequences

- 追加テーブルの Alembic マイグレーションが必要となる。
- 保持する対象は画像ごとの最新結果のみとし、全実行履歴の蓄積や自動再試行は導入しない。
- 送信済みの HTTP リクエストは、設定したタイムアウトまで終了を待つ場合がある。
- 警告がないことは内容の正確さを保証しないため、修正の判断はユーザーが行う。
