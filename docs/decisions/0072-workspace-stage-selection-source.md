# ADR 0072: ワークスペースのステージングボタンにおける選択状態の参照元

## 背景

Issue #570 において、サムネイルが選択されているように見えるにもかかわらず、ワークスペースのツールバーボタン「選択をステージングへ」を押すと選択なしメッセージが表示され、バッチタグのステージング領域へ画像を追加できない事象が報告された。Qt Designer のボタン接続では `QPushButton.clicked(bool)` のペイロード付きで `send_selected_to_batch_tag()` が呼び出され得る一方、コンテキストメニュー経路では表示中の選択済み ID を明示的に渡している。

## 決定

`DatasetStateManager` を選択状態の正規の参照元として維持する。スロットの `bool` ペイロードは明示的な選択 ID ではなくボタン押下イベントとして扱う。明示的な ID ペイロードとして認識するのは `list[int]` 引数のみとする。これにより、ツールバークリック時は引き続き `DatasetStateManager.selected_image_ids` を参照し、コンテキストメニュー呼び出し時は従来どおり ID を直接渡せるようにする。

## 根拠

この設計により、既存の右クリック操作や明示的 ID 指定の挙動を保ちつつ、`DatasetStateManager` を唯一の正規な選択参照元として維持できる。生の `QGraphicsScene.selectedItems()` や表示上の選択状態へフォールバックする補助関数は不採用とした。描画は `DatasetStateManager` で駆動されているのに対し、Qt シーンの選択状態はアプリ側の選択解除操作後に古くなることがあるためである。また、ツールバーのスロットに画像 ID を必須引数とさせる案も不採用とした。Qt Designer の接続は通常のボタンクリックであり、Qt の任意パラメータである checked 状態ペイロードとの互換性を保つ必要があるためである。

## 影響

テストでは、明示的 ID を渡す呼び出し、ツールバーからの `clicked(bool)` 呼び出し、および未選択警告経路をカバーする必要がある。将来追加されるワークスペースのステージング導線も、明示的 ID を渡すかメインウィンドウ経由で `DatasetStateManager` を参照するかのいずれかに統一し、新たな選択解決経路を追加してはならない。
