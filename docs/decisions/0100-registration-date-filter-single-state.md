# ADR 0100: 登録日フィルタはスライダーを唯一の状態にし、暦日の境界を 1 箇所で決める

## Context

検索パネルの登録日 (`Image.created_at`) フィルタには、範囲スライダー・サイドバーのヒストグラム・
(要望の) クイック選択の 3 つの UI がある。ヒストグラムの選択をスライダーとは別の第 2 の条件として
検索に渡すと、境界の丸め (小数秒)・保存形式の精度 (秒精度テキストとマイクロ秒付きの文字列比較)・
内部ビン境界の包含 (`<=`)・保存フィルタへの保存と復元が、それぞれ別に問題になった。
どれも「どの UI が何の範囲を、どの境界の意味で持つか」が決まっていないことが原因である。
あわせて、スライダーは秒単位 (1 日 ≒ 86,400 段階) で 1 日を選べず、UTC とローカル時刻の変換も
箇所ごとに異なっていた。

## Decision

- **状態は 2 つだけ**: 「登録日フィルタが有効か」と「スライダーの暦日範囲 (開始日・終了日とも含む)」。
  クイック選択とヒストグラムはスライダーの値を書き換えるだけで、独自の範囲を持たない。
  ヒストグラムの選択はファセット値に入れず、強調表示もスライダーの範囲から決める。
- **クイック選択は単一選択のチップ**: すべて / 今日 / 昨日 / 7日 / 30日 / カスタム。
  「すべて」はフィルタ無効。スライダーはカスタム選択時だけ表示し、スライダーを手で動かすか
  ヒストグラムのバーを選ぶとカスタムになる。保存フィルタの復元時は、範囲からプリセットを導出する。
- **粒度はローカル時刻の暦日**: スライダーの値は `date.toordinal()` で 1 目盛り = 1 日。
  「過去 N 日」は今日を含む直近 N 暦日。
- **境界の規則と時刻変換は 1 箇所** (`lorairo.domain.registration_date_range`、Qt 非依存の純粋関数):
  検索の境界は「開始日 00:00:00 以上、終了日の翌日 00:00:00 未満」の半開区間で、ローカル時刻から
  naive な UTC への変換はこの中で 1 回だけ行う。ヒストグラムのビンもこのモジュールで暦日単位に作り、
  検索と同じ条件式で数える。表示は逆変換で暦日に戻す。
- **DB 比較は保存形式の精度に依存しない**: 保存値と境界の両方を同じ正規形テキスト
  (`YYYY-MM-DD HH:MM:SS.ffffff`、naive UTC、小数部 6 桁) にそろえて比較する
  (SQLite の datetime は naive な UTC テキストで、秒精度・マイクロ秒付き・`T` 区切りが混在しうる)。
  `julianday()` はミリ秒へ丸めるので使わない (`.999999` が翌日に入る)。
  境界は aware なら UTC に変換してから正規形にする。
- 絞り込む列は `Image.created_at` (登録日)。排他の終了境界は内部用の `end_date_exclusive` で渡し、
  CLI の公開契約 (`start_date` / `end_date` は両端を含む) は変えない。
- 保存フィルタにはスライダーの暦日を ISO 日付で保存する。旧形式 (epoch 秒) はローカル暦日に変換して読む。

## Rationale

- 状態を 1 つにすれば、保存・復元・クリア・積集合の規則は不要になり、表示と検索条件が常に一致する。
- 暦日単位にすれば、ビン境界の小数秒や内部境界の包含は起こらない (境界は常にローカルの 00:00)。
- 第 2 の条件を残す案 (ヒストグラム選択を別条件として保持) は、保存・クリア・積集合の規則が増える。
  ヒストグラムを表示専用にする案は、既存のバー選択機能を削る。

## Consequences

- ヒストグラムのバーを選ぶと、ビンの範囲がスライダーに入り、件数見積もりが更新される。
  他のファセットのように即時に再検索はしない (スライダー操作と同じく適用ボタンで検索する)。
- ヒストグラムのビンは暦日単位になり、期間が短いときはビン数が 20 より少なくなる。
- 「今日」などは保存時の暦日として保存される (相対期間としては保存しない)。
- 日付フィルタの対象が `updated_at` から `created_at` に変わるため、CLI の日付指定も登録日で絞り込む。
