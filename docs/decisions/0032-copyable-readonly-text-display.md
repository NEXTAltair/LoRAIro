# ADR 0032: Copyable Read-Only Text Display Policy

## Context

LoRAIro の Qt GUI では、画像詳細・アノテーション結果・メタデータ・ログ的な補助情報など、ユーザーが読み取り専用のテキストを確認する場面が多い。これらの文字列は、検索条件の再利用、外部ツールへの貼り付け、Issue 報告、プロンプト調整などのためにコピーされる。

一方で、既存 UI では表示目的の `QLabel`、編集可能に見える `QTextEdit`、表形式の `QTableWidget` などが混在しており、以下の問題が起きやすい。

- 見えている文字列を選択・コピーできない。
- 読み取り専用情報なのに編集可能に見える。
- 複数行テキストや長文を `QLabel` で表示しており、選択・スクロール・折り返しが不自然になる。
- 表のセルコピー、行コピー、詳細全体コピーの責務が曖昧になる。
- 右クリックメニューの有無がウィジェットごとに揃わない。

Qt では、単純な表示には `QLabel` が軽量である一方、長文やエディタ的な表示では `QTextEdit`・`QPlainTextEdit`・`QLineEdit` を読み取り専用で運用する方が、選択・コピー・スクロール・コンテキストメニューを自然に扱える。LoRAIro では、この使い分けを GUI 実装の共通方針として明文化する。

## Decision

LoRAIro の Qt GUI では、読み取り専用テキストの表示を以下の方針に統一する。

1. **単一行かつコンパクトなラベルには `QLabel` を使い、選択可能にする。**
   ファイル名、モデル名、レーティング、スコア、短いステータス、カウント、固定ラベル横の値などは `QLabel` のまま表示してよい。ただし、ユーザーが値を再利用する可能性がある表示値には `Qt.TextSelectableByMouse` を設定する。キーボード選択が必要なフォーム状の値では `Qt.TextSelectableByKeyboard` も併用してよい。

2. **複数行・長文・エディタ的な表示には読み取り専用テキストウィジェットを使う。**
   キャプション、プロンプト、タグ一覧、エラー詳細、JSON 断片、複数行メタデータ、生成結果の詳細などは `QLabel` を使わない。用途に応じて `QTextEdit`・`QPlainTextEdit`・`QLineEdit` を読み取り専用で使う。
   - リッチテキストやリンクを扱う場合: 読み取り専用 `QTextEdit`
   - プレーンテキスト、ログ、JSON、固定幅表示が自然な場合: 読み取り専用 `QPlainTextEdit`
   - 単一行だがフォーム入力欄のように全選択・コピーしたい場合: 読み取り専用 `QLineEdit`

3. **読み取り専用テキストウィジェットは編集不可であることを明確にする。**
   `setReadOnly(True)` を必須とする。必要に応じてフレーム、パレット、フォーカスポリシー、プレースホルダーを調整し、「編集欄」ではなく「コピー可能な表示」であることを示す。読み取り専用であるにもかかわらず `textChanged` を通常入力として扱う実装は避ける。

4. **`QTableWidget` ではセル選択とコピー動作を明示する。**
   表形式データでは、画面の用途に合わせて `QTableWidget` やテーブルビューの選択単位(selection behavior)と選択モード(selection mode)を決める。メタデータや結果一覧のようにセル値の再利用が主目的であればセル選択を許可し、`Ctrl+C` で選択セルをタブ区切り・改行区切りのプレーンテキストとしてコピーする。行単位の操作が主目的の一覧では行選択を優先してよいが、その場合もコピーされる範囲をツールチップ・コンテキストメニュー・アクション名で明確にする。

5. **コンテキストメニューはコピー対象に合わせて標準化する。**
   コピー可能なテキストウィジェットは Qt 標準のコンテキストメニューを基本とする。`QLabel` やテーブルで標準メニューが不十分な場合は、少なくとも `Copy` を提供する。長文表示では `Select All` も提供する。独自アクションを追加する場合でも、標準のコピー操作(`Ctrl+C`)と競合させない。

6. **個別フィールドのコピーと詳細全体の一括コピーで責務を分ける。**
   個別フィールドのコピーは、その値を表示するウィジェット自身が担う。画像詳細・アノテーション詳細・メタデータサマリのような複数フィールドの一括コピーは、詳細パネルやダイアログなどの集約側(aggregate owner)が `Copy Details` / `Copy All` アクションとして提供する。

7. **詳細全体の一括コピーは安定したプレーンテキストを出力する。**
   一括コピーは UI の見た目ではなく、ラベル付きのプレーンテキストに整形する(例: `File: ...`、`Caption: ...`、`Tags: ...`)。表データを含む場合は TSV など貼り付け先で扱いやすい形式を使う。HTML や装飾付きリッチテキストを唯一のコピー形式にしない。

8. **読み取り専用表示のためにデータモデルを変更しない。**
   コピー可能化は GUI 表示層の責務である。DB スキーマ、アノテーションモデル、リポジトリ、画像処理パイプラインには影響させない。

## Rationale

### なぜ `QLabel` を全面禁止しないか

短い値や情報密度の高いパネルでは `QLabel` が最も軽量であり、既存の Qt Designer UI とも相性が良い。ただし `QLabel` の初期状態は選択不可であるため、ユーザーが値を再利用する表示では選択可能フラグを明示する必要がある。

### なぜ長文を読み取り専用エディタへ寄せるか

複数行テキストに対する選択範囲、スクロール、折り返し、全選択、コンテキストメニュー、キーボードコピーの期待値はエディタに近い。`QLabel` で長文を表示すると、レイアウトの伸縮やコピー操作が画面ごとに不安定になりやすい。読み取り専用の `QTextEdit` や `QPlainTextEdit` を使えば、編集を許可せずにこれらの操作を標準機能として提供できる。

### なぜテーブルのコピー方針を明示するか

表は「行を選ぶ UI」と「セル値をコピーする UI」の両方に使われる。選択単位が曖昧だと、ユーザーはコピー結果を予測できない。セル選択・行選択・コピー形式を画面ごとに決めておくことで、一覧操作と値の再利用を両立できる。

### なぜ個別コピーと一括コピーを分けるか

単一の値をコピーしたい場面と、Issue 報告や外部処理のために詳細全体をコピーしたい場面では必要な形式が異なる。個別ウィジェットが自身の表示値をコピー可能にし、集約側が全体をラベル付きプレーンテキストへまとめることで、責務と出力形式が明確になる。

## Consequences

### 良い点

- 画像詳細・アノテーション結果・メタデータの値を、見えている場所から直接コピーできる。
- 長文表示がエディタ相当の標準操作を備え、`QLabel` 起因のレイアウト問題を避けやすくなる。
- テーブルのコピー結果が予測しやすくなり、表計算ソフトや Issue 本文へ貼り付けやすくなる。
- 個別値のコピーと詳細全体のコピーで実装責務が明確に分かれる。

### 悪い点・トレードオフ

- `QTextEdit` と `QPlainTextEdit` は `QLabel` より重いため、高密度な一覧の全セルには使うべきではない。
- Qt Designer 上の既存 `QLabel` を置き換える場合、レイアウトとタブ順の再確認が必要になる。
- `QTableWidget` の `Ctrl+C` コピーは Qt 標準だけでは不足する場合があり、画面側でのアクション実装が必要になる。
- 詳細全体の一括コピー形式は、画面追加時に集約側で保守する必要がある。

### 実装方針

実装 Issue では以下の順序で進める。

1. 詳細パネルやダイアログの単一行値 `QLabel` に選択可能フラグを設定する。
2. キャプション、プロンプト、タグ一覧、メタデータなどの長文表示を読み取り専用テキストウィジェットへ寄せる。
3. テーブルビューおよび `QTableWidget` ごとに、選択単位・選択モード・`Ctrl+C` のコピー形式を明示する。
4. 必要なウィジェットへ `Copy` / `Select All` のコンテキストメニューアクションを追加する。
5. 詳細パネルやダイアログの集約側に `Copy Details` / `Copy All` を実装し、ラベル付きプレーンテキストをクリップボードへ設定する。
6. GUI テストでは、代表ウィジェットの読み取り専用状態、選択可能フラグ、コピーアクションの有無、詳細全体コピーの出力文字列を確認する。
