# ADR 0094: Clef annotation review の独立 API と一時的な個別警告

## Context

LoRAIro #1366 の確定した用途は、既存タグ・キャプションの内容を画像と照合し、
ユーザーが手動修正するための個別警告を表示すること。image-annotator-lib #167 で
判定の入力・返却形式と責任境界を整理する必要がある。

既存 `annotate()` の生成タグや品質スコアへ確率を流すと、質問・候補との対応や値の意味が
失われる。モデル capability の拡張だけでは、既存注釈に対する質問を表現できない。

## Decision

- ライブラリは `image_annotator_lib.decisions` に独立した型付き API を設ける。
  `annotate()`、生成モデルの registry/capability、通常の保存経路は変更しない。
- 呼出元の `request_id` と質問 ID をそのまま返す。真偽は真の確率、候補選択は選択 ID と
  全候補の確率、段階評価は値と値域・全段階の確率を保持する。
- Cloudflare を基本の接続先とし、`clef-flash` を既定モデルにする。
  画像・リクエストの上限や応答の ID・型・数値検証はライブラリが担当する。
- LoRAIro は画像・有効な注釈を DB から読み、各注釈行 ID を質問 ID に対応付ける。
  質問は「候補の内容が画像で支持されるか」。確率が 0.2 未満なら個別警告とする。
  しきい値は設定可能で、精度が検証済みであることを意味しない。
- GUI の明示操作と CLI の明示 ID 集合でのみ API を実行する。
  GUI は worker で通信し、画面をブロックしない。
  CLI は ADR 0057 / 0060 の作業集合上限に合わせ 1 回最大 500 枚とし、
  ID ファイルで選ぶ場合も通信・画像読み込み前に超過を拒否する。
- 正常な低確率、未評価、通信・解析失敗、途中失敗、キャンセル、古い判定を区別する。
  失敗を空の成功結果として扱わない。
- DB に判定結果を保存しない。注釈行・更新時刻、画像パス・ファイル状態から fingerprint を
  作り、編集や画像変更後の判定を無効にする。画面切替・終了時は worker の結果適用も無効化する。
- 自動修復・削除、出力の自動除外、好みの予測・傾向分析は導入しない。

## Rationale

既存の画像・注釈読み取りと手動編集を再利用し、Cloudflare 固有の JSON の解釈を
アプリへ持ち込まない。別 API なら未評価や失敗を型付きで保持でき、将来の比較用途も
DB や生成アノテーションに依存せず追加できる。

永続化を避けることで、未確定の警告基準に DB スキーマを固定しない。
古い判定の無効化を先に実装し、ユーザーが現在の注釈を確認しているかを保証する。

## Consequences

一度に 64 質問までなので、大量の注釈は分割して送信する。分割の途中で失敗すると
成功部分、失敗部分、未評価部分が混在する。画面や CLI はこの違いを表示する。
キャンセルは送信済み HTTP を中断せず、次の送信と結果適用を止める。
再起動・再選択時は再点検が必要。点検結果はタグ confidence や品質スコアには利用しない。

タグ `dog` (`tag_123`) への回答 `NoulAnswer(probability=0.03)` はタグの要確認表示。
キャプション「赤髪の女性」(`caption_456`) への回答 `NoulAnswer(probability=0.96)` は
警告対象外。いずれも元の行と文章を変更せず、理由文をモデルが生成できる前提にはしない。

仕様と運用手順: [Clef によるタグ・キャプション点検](../annotation-review.md)。
