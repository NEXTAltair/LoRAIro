# ADR 0094: Clef annotation review の独立 API と一時的な個別警告

> 2026-10-08 追記: Clef の実行先と認証設定は [ADR 0097](0097-clef-local-only.md) によりローカル専用へ変更した。

## Context

LoRAIro #1366 で確定した用途は、既存タグとキャプションの内容を画像と照合し、ユーザーが手動修正するための個別警告を表示することである。これに伴い、image-annotator-lib #167 で判定の入力・返却形式と責任境界を整理する必要がある。

既存の `annotate()` が返す生成タグや品質スコアへ確率を流用すると、質問や候補との対応および値の意味が失われる。モデルの機能定義(capability)を拡張するだけでは、既存注釈に対する質問を表現できない。

## Decision

### ライブラリ側の独立 API

- `image_annotator_lib.decisions` に独立した型付き API を設ける。既存の `annotate()`、生成モデルのレジストリ・機能定義(registry / capability)、通常の保存経路は変更しない。
- 呼び出し元の `request_id` と質問 ID をそのまま返す。回答の型ごとに、真偽は真の確率、候補選択は選択 ID と全候補の確率、段階評価は値・値域・全段階の確率を保持する。
- Cloudflare を基本の接続先とし、`clef-flash` を既定モデルとする。画像数・リクエスト数の上限管理および応答の ID・型・数値検証はライブラリ側が担当する。

### LoRAIro 側の呼び出しと警告判定

- LoRAIro は画像と有効な注釈を DB から読み取り、各注釈行 ID を質問 ID に対応付ける。質問内容は「候補の内容が画像で支持されるか」とする。
- 返却確率が 0.2 未満の場合を個別警告とする。しきい値は設定可能であり、既定値が精度検証済みであることを意味しない。
- API の実行は GUI の明示操作と CLI の明示 ID 集合のみに限定する。GUI はワーカー上で通信し、画面をブロックしない。
- CLI は ADR 0057 および ADR 0060 の作業集合上限に合わせて 1 回最大 500 枚とする。ID ファイルで対象を指定する場合も、通信と画像読み込みの前に上限超過を拒否する。

### 状態の区別と鮮度管理

- 正常な低確率、未評価、通信・解析失敗、途中失敗、キャンセル、古い判定を明確に区別し、失敗を空の成功結果として扱わない。
- DB へ判定結果は保存しない。注釈行と更新時刻、画像パスとファイル状態からフィンガープリントを生成し、編集や画像変更が行われた後の判定を無効化する。画面切替や終了時はワーカーの結果適用も無効化する。
- 自動修復、自動削除、出力からの自動除外、好みの予測・傾向分析は導入しない。

## Rationale

既存の画像・注釈読み取りと手動編集の仕組みを再利用し、Cloudflare 固有の JSON 解釈をアプリ側へ持ち込まないようにする。独立した API を設けることで未評価や失敗を型付きで保持でき、将来の比較用途も DB や生成アノテーションに依存せず追加できる。

永続化を避けることで、未確定の警告基準に DB スキーマを固定するリスクを回避する。古い判定の無効化を優先して実装し、ユーザーが現在の注釈内容を確認している状態を保証する。

## Consequences

- 一度に送信できる上限は 64 質問までのため、大量の注釈は分割して送信する。分割途中で失敗すると、成功部分・失敗部分・未評価部分が混在するため、画面と CLI はこの違いを区別して表示する。
- キャンセル操作は送信済みの HTTP 通信を強制中断せず、次の送信と結果適用を停止する。
- 初期実装では再起動や再選択のたびに再確認が必要だった。なお、確認結果はタグの信頼度(confidence)や品質スコアには利用しない。
- 結果の保存、固定対象の GUI バッチ実行、結果画面からの手動確認は [ADR 0095](0095-clef-review-batch-results.md) で改定する。

### 判定例

- タグ `dog`(`tag_123`)に対する回答 `NoulAnswer(probability=0.03)` は、タグの要確認として表示する。
- キャプション「赤髪の女性」(`caption_456`)に対する回答 `NoulAnswer(probability=0.96)` は、警告対象外とする。
- いずれの場合も元の行と文章は変更せず、モデルが理由文を生成できる前提にはしない。
