# ADR 0106: 生成メタデータを登録時に読み取り、再取り込みと再解析では原データとアノテーションを保つ

## Context

ADR 0105 で、生成メタデータのパーサと保存先(原データと解析結果)を整備した。画像の登録経路には GUI のワーカー、CLI / API、データセット取り込み、クロップなど複数あるが、いずれも `ImageDatabaseManager.register_original_image` を経由する(GUI ワーカーと CLI / API は `register_image_with_side_effects` 経由)。

既に登録済みの画像には解析結果が存在しない。また、同じ画像の再取り込みやパーサの更新時に、保存済みの原データとユーザーのタグ・キャプションを壊さない方針を定める必要がある。

## Decision

### 1. 登録時の読み取りを `register_original_image` に一本化する

登録時の読み取りは `register_original_image` の 1 箇所で行う。新規・別版・重複の分類と保存が確定した後に、登録元ファイルから生成メタデータを読み取って保存する(`record_generation_metadata`)。

GUI は既存の `DatabaseRegistrationWorker` の中で動作し、CLI / API、データセット取り込み、クロップもすべて同じ処理経路を通る。

### 2. 失敗しても画像登録は継続する

読み取りや復号に失敗した場合は、解析状態を `failed` として保存する。解析結果の保存中に DB エラー(`SQLAlchemyError`)が発生した場合は警告ログを出すにとどめ、登録結果自体は変更しない(解析結果は未解析のまま残る)。

### 3. 再取り込み(重複)は未解析のときのみ解析する

既に解析結果が存在する画像を再取り込みしても、原データと解析結果のどちらも変更しない。機能追加前に登録された未解析の画像に限り、再取り込み時に初めて解析を実行する。

### 4. 再解析は明示的な CLI 操作とする

再解析は `lorairo-cli images analyze-metadata` として提供し、保存済みの画像ファイル(`stored_image_path`)から読み直す。

- **画像 ID を省略した場合**: 未解析の画像を ID 昇順で最大 `--limit` 件(既定・上限 500)処理し、残り件数と `next_after_id`(処理した最大の画像 ID)を返す。ファイル欠落などで解析結果を作れなかった画像は未解析のまま残る(失敗を解析結果として記録しない)ため、`--after-id` に `next_after_id` を渡してページ送りを進める。
- **画像 ID を指定した場合**: 指定画像のうち未解析のものだけを処理する。パーサの版を上げた後など、既存の解析結果を置き換えたい場合は `--force` を指定する。
- **原データの保護**: いずれの場合も保存済みの原データは書き換えず、まだ存在しない取得元だけを追加する(ADR 0105)。
- **ファイル欠落の扱い**: 画像ファイルが見つからない場合は `file_missing` として報告し、解析結果は変更しない。

### 5. 生成プロンプトはタグ・キャプションへ自動反映しない

登録および再解析の処理は、`Tag` と `Caption` へ一切書き込まない。生成プロンプトを学習用のタグ・キャプションへ写す機能が必要になった場合は、別の明示的な操作として追加する。

### 6. AI 生成判定の参照インターフェースを提供する

AI 生成の判定(#1396)向けに `get_generation_evidence(image_id)` を提供する。戻り値は生成ツール、解析状態、および判定の可否(`is_ai_generated`、ADR 0105 と同一条件)とし、未解析の場合は `None` を返す。

## Consequences

- 登録 1 件あたり、画像ヘッダーの読み取りと 2 テーブルへの書き込みが追加される(画像データの展開は行わない)。
- クロップ画像は Pillow で再書き出しされるため生成情報を持たず、解析結果は `no_metadata` になる。
- 再取り込み時にファイル側の生成情報が変わっていても、解析済みであれば古い結果のまま残る。結果を更新するには `images analyze-metadata --force` を実行する。
- GUI から再解析を実行する入口は設けない(CLI のみ)。必要になった段階で後続対応する。
