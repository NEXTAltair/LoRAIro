# ADR 0096: Clef の検索警告と関連画像群のタグ候補・手動修正

## Context

Issue #1366 の 2026-10-08 合意は、検索中に怪しい注釈に気づき、その場で手動修正する
導線と、タグクラウド集計による未付与タグの候補提案を要求する。ADR 0094 / 0095 の
判定 API・固定バッチ・保存結果を再利用する。呼称は「アノテーションチェック」とする。

## Decision

- 検索時の保存結果・鮮度確認は worker で行い、Cloudflare を呼ばない。サムネイルの
  要確認件数とフィルターは現在の判定だけを使う。未チェック・未評価・失敗・古い判定を
  警告なしと区別し、画像ごとの保存と手動編集通知で表示を更新する。
- 詳細欄は注釈行 ID に対応した警告をタグと全キャプションに示す。タグ翻訳や別の
  refinement 表示が更新されても警告を維持する。単語単位の位置や説明文を推測しない。
- 明示したキーワードまたはタグ AND 条件から TagCloudService の集計を再利用する。
  候補数は既定32・最大64、各対象の既存タグを除いてから上限を適用する。
  候補条件と対象を開始時に固定し、通信前に snapshot を作る。全タグは送信しない。
- 未付与タグを `suggestion` 種別の別質問 ID で評価する。既定0.8以上を追加候補とし、
  既存タグの要確認件数には含めない。画像別結果の既存 JSON に条件と基準を保存する。
  新しい通信 API、生成モデル経路、追加テーブルは設けない。
- 追加候補の採用は最新保存日時・fingerprint・判定設定を再検証してから手動タグ追加へ
  渡す。判定確率をタグ confidence や手動スコアへコピーしない。
- キャプションは画像 ID・行 ID・編集前本文を照合する原子的更新で手動編集する。
  元行を残す追加保存では修正が成立しないため、行 ID とモデル由来を保持して置換する。
- ステージングから対象・候補条件を準備し、「チェックを実行」で開始する。
  準備中・進捗・停止中をタブを移っても表示する。未測定の所要時間は推定しない。

## Consequences

旧保存形式は候補なしとして引き続き読める。画像・注釈や基準の変更は結果を古くし、
追加候補採用も無効にする。自動修復・自動採用・reviewed 更新・出力の自動除外は導入しない。
Cloudflare 実 API の精度と速度は今回のオフライン検証の対象外。

仕様: [Clef によるアノテーションチェック](../annotation-review.md)。
