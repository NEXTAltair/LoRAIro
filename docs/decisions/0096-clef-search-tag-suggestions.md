# ADR 0096: Clef の検索警告と関連画像群のタグ候補・手動修正

> 2026-10-08 追記: Clef の実行先と認証設定は [ADR 0097](0097-clef-local-only.md) によりローカル専用へ変更した。

## Context

Issue #1366 の 2026-10-08 合意では、検索中に怪しい注釈へ気づいてその場で手動修正する導線と、タグクラウド集計による未付与タグの候補提案が求められている。ADR 0094 および ADR 0095 で定めた判定 API・固定バッチ・保存結果を再利用し、画面上の呼称は「アノテーションチェック」とする。

## Decision

### 検索画面と詳細欄での警告表示

- 検索時の保存結果の読み込みと鮮度確認はワーカーで行い、Cloudflare は呼び出さない。サムネイルの要確認件数とフィルターには現在の判定のみを用いる。
- 未チェック・未評価・失敗・古い判定を「警告なし」と明確に区別し、画像ごとの保存や手動編集通知に応じて表示を更新する。
- 詳細欄では、注釈行 ID に対応した警告をタグおよび全キャプションに表示する。タグ翻訳や別の精査(refinement)表示が更新されても警告表示は維持し、単語単位の位置や説明文は推測しない。

### 関連画像群からの未付与タグ候補提案

- 明示したキーワードまたはタグ AND 条件から、`TagCloudService` の集計を再利用して候補を生成する。候補数は既定 32、最大 64 とし、各対象画像の既存タグを除外してから上限を適用する。
- 候補条件と対象画像は開始時に固定し、通信前にスナップショットを作成する。全タグを送信することはしない。
- 未付与タグは `suggestion` 種別の別質問 ID として評価する。既定 0.8 以上を追加候補とし、既存タグの要確認件数には含めない。
- 候補の条件と基準は画像別結果の既存 JSON に保存する。新しい通信 API、生成モデル経路、追加テーブルは設けない。

### 手動修正と追加候補の採用

- 追加候補を採用する際は、最新保存日時・フィンガープリント・判定設定を再検証してから手動タグ追加へ渡す。判定確率をタグの信頼度(confidence)や手動スコアへコピーしない。
- キャプションの手動編集は、画像 ID・行 ID・編集前本文を照合する原子的更新で行う。元行を残したまま追加保存する方式では修正が成立しないため、行 ID とモデル由来を保持して置換する。

### 実行導線と進捗表示

ステージングから対象と候補条件を準備し、「チェックを実行」ボタンで処理を開始する。準備中・進捗・停止中の状態はタブを切り替えても表示し続け、未測定の所要時間は推定表示しない。

## Consequences

- 旧保存形式のデータは「候補なし」として引き続き読み込める。
- 画像・注釈・判定基準のいずれかが変更されると結果は古い判定となり、追加候補の採用も無効になる。
- 自動修復、自動採用、`reviewed` 状態の自動更新、および出力からの自動除外は導入しない。
- Cloudflare 実 API の精度と速度は、今回のオフライン検証の対象外である。
