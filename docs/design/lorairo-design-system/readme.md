# LoRAIro Design System

**LoRAIro** から抽出したデザインシステムである。LoRAIro は LoRA やファインチューン学習用の画像データセットを準備するための、日本語向けデスクトップツールである。リサイズ、AI 自動タグ付け、キャプションやスコアの生成、SQLite ベースのメタデータ管理を自動化する。インターフェースとして **PySide6(Qt)GUI** とエージェント向けの **Typer CLI** の両方を備える。

> **LoRAIro** という名前は「**LoRA 用画像を色々(いろいろ)する**」スクリプトを略したものである。ブランドの色調は一般的な開発ツールに多い冷たいブルーグレーではなく、温かみのある「和紙に墨」のパレットに寄せている。

本デザインシステムは、トークン、ファウンデーション見本、再利用可能な React プリミティブ、デスクトップ UI のインタラクティブな再現によって、アプリの視覚言語をコード化したものである。デザインエージェントがブランドに沿った LoRAIro の画面、モック、スライド、プロトタイプを作成できるようにする。

## プロダクトの文脈

- **1 プロダクト・1 サーフェス**: ウェブサイトでもモバイルアプリでもない、単一ウィンドウの **デスクトップアプリケーション** である。情報密度が高く、マルチペイン構成でキーボード駆動を前提とする。UI は日本語ファーストであり、識別子・schema 名・モデル名・コードには英語を維持する。
- **ワークフロー中心**: 上部のタブバーに沿ってパイプラインを進める構成である。**検索 Search → マップ Map → アノテーション Annotate → ジョブ Jobs → 結果 Results → エラー Errors → エクスポート Export → CLI**(⌘1–⌘8)の順に並ぶ。
- **コアループ**: データセットを検索・絞り込みし、画像をステージングする。次にローカルおよび API モデルのアノテーションパイプライン(TAGGER → CAPTION → SCORER → RATING → UPSCALE)を構成し、追跡可能な Job として実行する。最後に結果をトリアージしてエクスポートする。
- **2 つの動作面**: GUI に加え、エージェントから駆動できる構造化 CLI を備える(stdout に `item` / `result` / `error` の JSONL を出力する)。ダークなターミナルペインは、温かい和紙の世界の中で唯一ダークに転じる領域である。

## コンテンツの基本

LoRAIro におけるコピー執筆の原則は以下のとおりである。

- **日本語ファースト、技術用語は英語**: UI のクローム、ラベル、補助テキストは日本語とする(「検索」「アノテーション」「実行中」「待機」「失敗」など)。一方、モデル名(`claude-haiku-4-5`、`wd-eva02-large-v3`)、schema フィールド(`is_edited_manually`)、ジョブ種別(`model_install`、`provider_batch`)、CLI コマンドなどの識別子は英語のまま維持する。目安として、*3 語以上の英語フレーズには日本語を併記し、2 語以下の識別子・schema 参照・コード・モデル名は英語のまま* とする。
- **簡潔で事実ベース**: ラベルは「検索結果」「実行中 / キュー」「対象 128 枚(検索から追加)」のような名詞または名詞句にする。マーケティング的な語調、感嘆、二人称の呼びかけは使わず、事実と件数のみを述べる。
- **数値は一級市民で等幅**: 件数(「1,247 件 / 表示 1–48」)、コスト(「$0.0011/img · ~0.8s」)、進捗(「45% (350.0/780.0 MB)」)、時刻(「14:32」)、スコア(「0.82」)などの数値は常に JetBrains Mono で表示する。日本語文脈では全角の「件」「枚」カウンタを使う。
- **ステータスは固定語彙**: 小さく固定された語彙をそのまま繰り返し使う。モデルの可用性などは `installed` / `API ready` / `needs key` / `discontinued`、ジョブ状態は「実行中 / 待機 / 完了 / 失敗 / 中止」を用いる。終端状態の語(ADR 0034)は `FAILED` / `CANCELED` / `TERMINATED` / `UNRESPONSIVE` である。
- **絵文字は使わない**: 非テキストのグリフには機能的な Unicode 記号のみを使う(「アイコノグラフィ」参照)。CLI は Windows の cp932 環境でも文字化けしないよう、`✓✗` ではなく ASCII マーカー `[OK]` `[--]` `[!]` `[i]` を用いる。
- **声のトーン例**: モデルピッカー下の補助行では *「○ needs key をクリックすると設定の該当プロバイダ欄が開きます」* のように記述する。機能的・指示的な文体で、日本語の案内と英語のステータス語を組み合わせる。

## 視覚のファウンデーション

- **パレット(温かい和紙と墨)**: 背景はオフホワイトの紙(`--paper #fbfaf6`)と少し濃いバンド(`--paper-shade #f1efe6`)、カードは純白とする。テキストはニアブラックの墨と 2 階調の柔らかいグレーで構成する。唯一のアクセントは **テラコッタ / クレイ**(`--accent #c25e3f`、`oklch(0.62 0.14 32)`)であり、主要アクション・選択・アクティブタブの下線に使う。それ以外はすべて暖色の中立スケールに抑え、意図的に *ブルー系の開発ツールにしない*。
- **ステータス色**: 一般的な 4 色を落ち着いた土っぽい色調に抑えて定義する。`ok` = モスグリーン `#3c8a55`、`warn` = オーカー `#b87f1f`、`err` = ブリック `#b8402c`、`info` = スレートブルー `#3d6f9e`。各色はソリッド・ソフト塗り・同系の罫線の 3 点セットで提供する。
- **ダークなサーフェスは 1 つだけ**: ダーク背景を用いるのはターミナル / JSONL ペイン(`--terminal #23211d`)のみである。このペインは独自のシンタックスパレット(key / string / number / boolean)を持つ。それ以外の領域は反転しない。
- **タイポグラフィ**: 本文は日本語ファーストの **Noto Sans JP**、コードと数値メタは **JetBrains Mono** を使う。コンパクトなデスクトップ向けスケールを採用し、13px をベース、11px をスモール、14/18px を見出し、10px を数値メタとする。初期ワイヤーフレームで使っていた手書き書体(Kalam)は、このクリーンでモダンな組み合わせへ移行するため Theme v1 で **廃止** した。
- **形**: 角丸はカード・ボタン・入力が 6px、チップが 10px、小バッジが 3px、外側のウィンドウが 8px である。要素の区切りは罫線が担い、全体に 1px の `--line` ヘアラインを使う。アクティブタブには 2px のアクセント下線、選択サムネには 2px のアクセント枠を引く。
- **スペーシング**: 4 / 8 / 12 / 16 / 24 の厳格なスケールを用いる。カードは 12px、入力は 3–6px とし、密度の高いデスクトップ級のパディングを維持する。
- **エレベーションはほぼフラット**: アプリ全体で「影ではなく罫線」を原則とする。唯一の影は浮遊するウィンドウシェル(`0 2px 10px rgba(26,26,26,.07)`)のみである。これに加え、ローディングオーバーレイ用の半透明の墨スクリムを備える。
- **背景**: フラットな紙の塗りを基本とし、グラデーション、写真、イラスト、テクスチャは使わない。唯一の例外として、サムネのプレースホルダに控えめな `135deg` の `paper-shade` グラデーションを許可する。画像は *ユーザー自身のデータセット* を正方形サムネで表示し、クロームを中立に保つことで画像にすべての色を担わせる。
- **ステート**:
  - Hover: ボタンは罫線とテキストをアクセント色へ寄せ、行・ゴーストボタン・サムネは `paper-shade` で塗る。
  - Press: `accent-soft` で塗る。
  - Focus: アクセント罫線と柔らかなアクセントのリングを表示する。
  - Selected: 行は `accent-soft`、タイルはアクセント枠で示す。
  - Disabled: `paper-shade` の塗りと淡い墨の文字にする。`discontinued` モデルは履歴を消さない方針に従い、取り消し線を保持する。
- **モーション**: 最小限かつ素早い遷移にとどめる。色や罫線の遷移は約 `0.12s`、進捗の塗りは約 `0.3s` とする。バウンス、装飾的なループ、パララックスは使わない。ショーではなく道具としての振る舞いを優先する。
- **チップの文法**: ドットの塗りつぶしで可用性を表す。**● = 利用可**(`installed` / `ready` / `running`。`ok` または `info` 色)、**○ = 要対応 または 無効**(`needs key` = `warn`、`queued` = `neutral`、`discontinued` = 淡色)。この規則はアプリ全体で統一して使う。

## アイコノグラフィ

LoRAIro には **アイコンフォント、SVG アイコンセット、ラスターアイコン、ロゴ画像のいずれも存在しない**。これは意図的な設計であり、今後も維持する。

- **ロゴ**: 純粋な文字ワードマークである。`LoRA` を墨色、`Iro` を `--accent` で表し、マークやシンボルは付けない(`guidelines/brand-logo.card.html` 参照)。
- **機能グリフ**: プレーンな Unicode 記号を用い、意味を持つ箇所にのみ控えめに配置する。
  - `⚙` 設定の歯車(タイトルバー)
  - `▾` セレクトのキャレット
  - `→` パイプラインのステージ矢印
  - `▶` 実行
  - `▸` レビュー・展開
  - `×` タグ削除
  - `●` / `○` ステータスドット
  - `↝` シャドウ・自動取得ステージ
- **CLI マーカー**: Windows の cp932 エンコーディングで文字化けしないよう、ASCII 記号 `[OK]` `[--]` `[!]` `[i]` を使用する(出典: `src/lorairo/cli/_glyphs.py`)。
- **絵文字の禁止**: 絵文字はどの画面・出力でも使わない。
- **`assets/` の扱い**: 出荷するブランドバイナリがないため、`assets/` は意図的にほぼ空である。*拡張* モック用にプロダクト自身が持たない補助 UI アイコン(フォルダや検索など)が必要な場合は、**[Lucide](https://lucide.dev)** のような細線の CDN セットを使い、**チームに置き換えを明示** すること。ただし、実アプリに存在する要素には上記の Unicode グリフを優先する。

## インデックス / マニフェスト

### ルート構成

- **`styles.css`**: 利用側がリンクする唯一のエントリポイントである。3 つのトークンファイルのみを `@import` する。
- **`tokens/`**: `colors.css`、`typography.css`(Google Fonts の import を含む)、`spacing.css` を収める。ベーストークンとセマンティックエイリアスを定義する。
- **`readme.md`**: 本ガイド。
- **`SKILL.md`**: Claude Code で使うための Agent-Skill フロントマター。
- **`assets/`**: 意図的に最小限にとどめている(「アイコノグラフィ」参照)。

  - `TagInput`(タグ集合の編集、Enter / カンマで確定、canonical 固定)
- **feedback/**
  - `Chip`(ok / warn / err / info / neutral / muted / accent + ドット文法)
  - `TagChip`
  - `TypeBadge`
  - `ProgressBar`(info / ok、ストライプ対応)
  - `SummaryStat`(KPI タイル)
  - `Toast`(一時通知、ステータス色の左ストライプ + グリフ、自動消去 / floating)
- **data/**
  - `Card`
  - `DataTable`(columns / rows、レンダースロット対応)
  - `Thumbnail`(画像タイル + 数値メタ)

### ファウンデーション見本カードと UI キット

- **ファウンデーション見本カード(`guidelines/`、Design System タブに表示)**: surface / ink & line / accent / status / terminal の各色、sans / mono / type-scale、spacing / radii、チップ文法、ロゴを収める。
- **UI キット(`ui_kits/lorairo-app/`)**: デスクトップアプリのインタラクティブな再現である。`index.html` がシェルと各画面をマウントし、タブ(検索 / マップ / アノテーション / ジョブ / 結果 / エラー / エクスポート / CLI)と `⚙` 設定モーダルをクリックして操作できる。主な画面ファイルは次のとおりである。
  - `AppShell.jsx`(タイトルバー + ナビ)、`SettingsScreen.jsx`(API キー / モデルルート / インストーラモーダル)
  - `SearchScreen.jsx`(フィルタサイドバー + サムネグリッド)、`MapScreen.jsx`(タグクラスタ散布図)、`AnnotateScreen.jsx`(パイプライン + モデルピッカー)
  - `JobsScreen.jsx`(サマリ + ステージ別の実行中 + 履歴)、`ResultsScreen.jsx`(品質トリアージ)、`ErrorsScreen.jsx`(グループ化された失敗トリアージ)
  - `ExportScreen.jsx`(ステージング対象 + 出力ファイル + フォーマット)、`CLIScreen.jsx`(JSONL コントラクト)、`tagI18n.jsx`(タグ表示翻訳の共有モジュール、Search / Tag Edit 共用)

## 使い方

利用側は単一のスタイルシートをリンクし、バンドルのネームスペースからコンポーネントを読み込む。

```html
<link rel="stylesheet" href="styles.css">
<script src="_ds_bundle.js"></script>
<script>
  const { Button, Chip, Card, DataTable, Tabs } = window.LoRAIroDesignSystem_64d8f7;
</script>
```

トークンは CSS カスタムプロパティ(`var(--accent)`、`var(--paper)`、`var(--font-mono)`)経由で参照し、hex 値を直書きしないこと。`_ds_bundle.js` と `_ds_manifest.json` はコンパイラが生成するため、手で編集してはならない。
