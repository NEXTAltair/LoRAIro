# セキュリティルール

実装コードのセキュリティ検査は、散文の禁止リストではなく Ruff の `S`(flake8-bandit)ルールで機械的に検出する。

以下の危険なパターンはすべて Lint で検出・阻止される。
- `eval` / `exec`(S102、S307)
- `pickle.load`(S301)
- `shell=True` / `os.system`(S602、S605)
- `SafeLoader` 指定なしの `yaml.load`(S506)
- ハードコードされたパスワード(S105〜S107)
- SQL の文字列連結(S608)

これらの設定は [coding-style.md](coding-style.md) の `select` に含まれており、指摘の扱いも同ファイルの「Lint 結果の扱い」に従う(原則として抑制せず、例外時はルールコードを限定して理由を明記する)。

本ファイルでは、Lint だけでは判断できないセキュリティ上の規約だけを定める。

## 機密情報の管理

- API キーやトークンはソースコードに書かず、環境変数から読み込む。未設定の場合は黙ってフォールバックせず、起動時に明示的に失敗させる。
- `.env` は `.gitignore` に含める。設定例は `.env.example` として値を空にした状態で配置する。

## ユーザー入力の検証とエラー出力

- ユーザーが指定したパスは `Path.resolve()` で正規化し、許可ディレクトリの外を指していないかを `is_relative_to` で確認してから使用する。
- ユーザー向けのエラーメッセージには、内部パス、スタックトレース、接続文字列を含めない。詳細はログ側に記録する([logging.md](logging.md) を参照)。
- ログには API キー、トークン、個人情報などの機密情報を出力しない。

## 危険な関数を例外的に使う場合

Lint の `S` 指摘を抑制して危険な関数を使用できるのは、入力が完全に信頼できる(自プロジェクトが生成したファイルや定数のみなど)と文書化できる場合に限る。使用する際は抑制コメントに理由を明記し、コードレビューで明示的な承認を得る。

## セキュリティ問題を発見したときの対応

重大な脆弱性を発見した場合は、進行中の作業より優先して修正し、コードレビューで確認する。

> **プロジェクト固有:** Ruff の `S` ルール以外に利用する静的解析ツール(Semgrep など)や脆弱性スキャンの実行コマンドは、導入先で追記する。
